## 1. 개요

### 1.1 제품 개요

**주식 실적 플래너**는 구글 스프레드시트(Google Sheets)에 정리된 개인 투자 계좌(연금/개인투자) 실적 데이터를 자동으로 수집·적재하고, 웹 대시보드에서 조회·분석할 수 있게 해주는 개인용 투자 통계 서비스입니다.

기존에는 구글 스프레드시트를 직접 열어 계좌별 실적을 수기로 확인해야 했으나, 본 서비스는 이를 데이터베이스화하여 대시보드, 일별/주별/월별 추이를 시각적으로 조회할 수 있도록 합니다.

### 1.2 핵심 가치

- **자동 수집**: 구글 스프레드시트의 투자 실적 데이터를 스케줄 작업으로 자동 수집하여 DB에 적재
- **이력 관리**: 스프레드시트는 최신 스냅샷만 남지만, DB에는 일자별 이력이 누적되어 추이 분석 가능
- **시각화 조회**: 계좌별/기간별(일·주·월) 실적을 대시보드와 꺾은선 그래프로 한눈에 확인

### 1.3 사용자

- 1인 개인 투자자(서비스 소유자 본인) 전용 MVP. 다중 사용자/로그인 체계는 범위 밖(Out of Scope)으로 별도 확장 검토.

## 2. 배경 및 문제 정의

### 2.1 문제

1. **수기 확인의 번거로움**: 여러 계좌(연금, 개인연금, DC, ISA, 처리투자, 은퇴투자 등)의 실적을 구글 스프레드시트에서 매번 직접 열람해야 함
2. **이력 데이터 부재**: 스프레드시트는 시점 스냅샷 위주라 일별/주별/월별 추이를 비교하기 어려움
3. **시각화 부재**: 표 형태의 데이터만 존재하여 자산 비중, 수익 추이 등을 직관적으로 파악하기 어려움

### 2.2 기존 데이터 원본

|---|---|---|

| 계좌별 자산 비중 | Google Sheets ("4.계좌별 비중" 탭) | 계좌별 현재금액 비중 |

## 3. 목표 및 성공 지표

### 3.1 MVP 목표

- 구글 스프레드시트 데이터를 스케줄 작업으로 Supabase DB에 안정적으로 적재
- 웹에서 계좌별 실적을 대시보드/일별/주별/월별 화면으로 조회 가능하게 배포

### 3.2 성공 지표 (Key Metrics)

| 지표 | 목표 |
|---|---|
| 데이터 수집 성공률 | 스케줄 실행 시 99% 이상 정상 적재 |
| 데이터 최신성 | 최근 수집 시점과 조회 화면 기준일 차이 1일 이내 |
| 대시보드 로딩 시간 | 3초 이내 |
| 조회 화면 커버리지 | 대시보드/일별/주별/월별 4개 화면 100% 구현 |

## 4. 전체 아키텍처 개요

```
[Google Sheets 원본 데이터]
        │  (읽기)
        ▼
[데이터 수집 스크립트]  ← Claude Code(Windows) 스케줄 작업으로 주기 실행
        │  (파싱/변환)
        ▼
[Supabase (PostgreSQL DB)]  ← 일자별 이력 적재
        │  (조회 API / DB 직접 조회)
        ▼
[웹 애플리케이션]  ← Vercel 배포
        │
        ▼
[사용자 브라우저]  ← 대시보드/일별/주별/월별 조회
```

### 4.1 데이터 수집 파이프라인

- **원본**: Google Sheets (`1.투자현황(현재)` 탭, `4.계좌별 비중` 탭)
- **수집 방식**: Claude Code Windows 버전의 스케줄(Cron 유사) 기능을 이용해 주기적으로 실행되는 수집 스크립트
- **처리**: 시트 값을 파싱하여 계좌별 실적(투자원금/현재금액/수익금액/수익률)을 당일 스냅샷으로 Supabase에 저장
- **적재 방식**: 동일 계좌·동일 날짜 데이터는 upsert, 날짜가 달라지면 신규 row로 누적 → 일별/주별/월별 추이 데이터의 기반이 됨

### 4.2 조회 애플리케이션

- **배포**: Vercel
- **DB 연동**: Supabase (PostgreSQL + REST/JS 클라이언트)
- 웹 앱은 데이터를 **입력/수정하지 않고 조회 전용**으로 동작 (데이터 입력은 스케줄 수집 파이프라인이 전담)

### 5.2 화면 1: 계좌별 실적 대시보드 (현재 실적)

**목적**: 전체 투자 현황을 한눈에 파악하는 랜딩 화면

**구성 요소**:

1. **헤더**
   - 서비스명(Investment Dashboard), 부제(투자 실적 현황), 데이터 기준일시(Google Sheets 최종 수집 시각 표시)
   - 탭 내비게이션: 현재 실적 / 일별 추적 / 주별 추적 / 월별 실적

2. **요약 카드 3종**
   - 총 현재금액 (전체 계좌 합계)
   - 총 수익금액 (금액 + 수익률 %)
   - 전일 대비 (증감액 + 증감률 %)

3. **연금 vs 개인투자 비중 (도넛 차트)**
   - 연금 계좌 합계와 개인투자 계좌 합계를 비율로 시각화
   - 범례: 연금 / 개인투자

4. **전체 계좌 자산 비중 (차트)**
   - 전체 계좌별 현재금액 비중 시각화 (도넛/파이 또는 트리맵 등)

5. **계좌별 현재금액 비중 (막대 리스트)**
   - 계좌명(계좌번호 일부 마스킹 표기) + 금액 + 비율 막대
   - 예: 퇴직연금(220-91), 개인연금(기존)(220-34), 개인연금(신)(112-8680), DC계좌(496-3028), 퇴직연금(삼성)(648-8656), 처리투자(미래에셋), 은퇴투자(미래에셋), ISA계좌(648-8656)

6. **계좌별 수익금액 비중 (차트)**
   - 계좌별 수익금액 기준 비중 시각화

7. **상세 현황 테이블**
   - 그룹: 연금 계좌 / 개인투자 계좌 (각 그룹 소계 + 전체 합계 행 포함)
   - 컬럼: 계좌명 | 투자원금 | 현재금액 | 수익금액 | 수익률
   - 계좌 그룹 접기/펼치기(▷/▶) 지원
   - 수익금액/수익률은 양수일 때 강조색(빨강 계열), 표기: `+금액`, `+비율%`

**수락 기준**:
- [ ] 요약 카드 3종이 최신 수집 데이터 기준으로 정확히 계산되어 표시된다
- [ ] 연금/개인투자 비중 도넛 차트가 실제 데이터 비율과 일치한다
- [ ] 계좌별 비중 막대 리스트가 금액 내림차순 등 일관된 정렬로 표시된다
- [ ] 상세 테이블에서 연금/개인투자 그룹 소계와 전체 합계가 개별 계좌 합과 일치한다
- [ ] 데이터가 없을 경우(수집 전) 빈 상태(empty state) UI가 표시된다

### 5.3 화면 2: 계좌별 실적 (일별)

**목적**: 일 단위로 계좌별 실적 추이를 조회

**구성 요소**:

1. **조회 조건 영역**
   - 계좌 선택 (전체/개별 계좌, 다중 선택 가능)
   - 일자 선택 (기간 조회 - 시작일/종료일)

2. **꺾은선 그래프**
   - 전체 계좌, 연금, 개인투자 구분별 금액 및 수익률 추이를 일별 꺾은선 그래프로 표시
   - Y축: 금액 / 수익률 토글 또는 병행 표시

3. **계좌별 일별 실적 테이블**
   - 컬럼: 날짜 | 구분(전체합계/개인투자/연금 또는 개별 계좌) | 투자원금 | 현재금액 | 수익금액 | 수익률
   - 날짜 내림차순 정렬 (최신일 우선), 날짜별 그룹핑
   - 전체합계 행은 굵게 강조 표시

**수락 기준**:
- [ ] 조회 조건(계좌, 기간)을 변경하면 그래프와 테이블이 함께 갱신된다
- [ ] 조회 기간 내 데이터가 없는 날짜는 결측으로 명확히 구분되거나 제외된다
- [ ] 꺾은선 그래프의 데이터 포인트가 테이블 값과 일치한다
- [ ] 기본 조회 기간(예: 최근 30일)이 설정되어 있어 최초 진입 시 바로 데이터가 보인다

---

### 5.4 화면 3: 계좌별 실적 (주별)

**목적**: 주 단위로 집계된 계좌별 실적 추이를 조회

**구성 요소**:

1. **조회 조건 영역**
   - 일 조회 조건 기반으로 주 단위 집계 대상 기간 지정

2. **계좌 주별 꺾은선 그래프**
   - 금액, 수익률 주별 추이

3. **계좌 주별 실적 테이블**
   - 컬럼: 주차(또는 주 시작일~종료일) | 구분 | 투자원금 | 현재금액 | 수익금액 | 수익률

**집계 규칙**:
- 주 단위 실적은 해당 주의 마지막 수집일(예: 매주 일요일 또는 마지막 영업일) 스냅샷을 그 주 대표값으로 사용
- 주차 표기 기준(ISO 주차 등)은 구현 단계에서 확정

**수락 기준**:
- [ ] 주 단위 집계 값이 일별 원본 데이터로부터 일관된 규칙으로 산출된다
- [ ] 그래프와 테이블의 주차 표기가 동일한 기준을 따른다
- [ ] 조회 조건 변경 시 그래프/테이블이 함께 갱신된다

---

### 5.5 화면 4: 계좌별 실적 (월별)

**목적**: 월 단위로 집계된 계좌별 실적 추이를 조회

**구성 요소**:

1. **조회 조건 영역**
   - 조회 필드: 년도, 시작월, 종료월

2. **계좌 월별 꺾은선 그래프**
   - 금액, 수익률 월별 추이

3. **계좌 월별 실적 테이블**
   - 컬럼: 년월 | 구분 | 투자원금 | 현재금액 | 수익금액 | 수익률

**집계 규칙**:
- 월 단위 실적은 해당 월의 마지막 수집일 스냅샷을 그 달 대표값으로 사용

**수락 기준**:
- [ ] 년도/시작월/종료월 조건으로 조회 시 해당 범위의 월별 데이터만 표시된다
- [ ] 월 단위 집계 값이 일별 원본 데이터로부터 일관된 규칙으로 산출된다
- [ ] 그래프와 테이블의 값이 서로 일치한다

## 6. 데이터 요구사항

### 6.1 원본 데이터 항목 (Google Sheets 기준)

- 계좌명 (예: 퇴직연금, 개인연금(기존), 개인연금(신), DC계좌, 퇴직연금(삼성), 처리투자, 은퇴투자, ISA계좌)
- 계좌번호(또는 식별 코드 일부)
- 계좌 구분: 연금 / 개인투자
- 투자원금
- 현재금액
- 수익금액 (현재금액 − 투자원금)
- 수익률 (수익금액 / 투자원금 × 100)
- 수집 기준일시

### 6.2 Supabase DB 설계 방향 (개략)

> 상세 스키마는 개발 단계에서 확정. MVP 기준 최소 테이블 구조 제안.

- **accounts** (계좌 마스터)
  - id, account_name, account_no_masked, account_type(연금/개인투자), created_at
- **account_snapshots** (계좌별 일별 실적 스냅샷 - 이력 테이블)
  - id, account_id(FK), snapshot_date, principal_amount(투자원금), current_amount(현재금액), profit_amount(수익금액), profit_rate(수익률), collected_at

- 일별 화면은 `account_snapshots`를 그대로 조회
- 주별/월별 화면은 `account_snapshots`를 주/월 단위로 집계(뷰 또는 쿼리)하여 조회

### 6.3 데이터 수집 규칙

- 스케줄 작업은 1일 1회 이상 실행되어 당일 스냅샷을 적재
- 동일 계좌 + 동일 수집일 데이터가 이미 존재하면 최신 값으로 갱신(upsert), 중복 row 생성 금지
- 계좌가 신규로 추가/삭제되는 경우를 대비해 `accounts` 마스터는 수집 시점에 자동 동기화(신규 계좌 발견 시 자동 등록)

| 보안 | Supabase 접근 키(Service Role Key 등)는 서버 사이드에서만 사용, 클라이언트에는 노출 금지. Google Sheets 인증 정보는 수집 스크립트 실행 환경에만 안전하게 보관 |
| 가용성 | 수집 스케줄 실패 시에도 기존 조회 화면은 마지막 성공 데이터로 정상 동작 |
| 데이터 정합성 | 원본 시트 값과 DB 적재 값의 금액/수익률 오차 없음 (반올림 규칙 일치) |

## 8. 기술 스택

| 영역 | 기술 |
|---|---|
| 데이터 원본 | Google Sheets |
| 데이터 수집 | Claude Code (Windows) 스케줄 작업 기반 수집 스크립트 |
| 데이터베이스 | Supabase (PostgreSQL) |
| 프론트엔드 | Next.js, TypeScript, Tailwind CSS, shadcn/ui |
| 상태관리 | Zustand |
| 폼 | React Hook Form + Zod |
| 차트 | 꺾은선 그래프/도넛 차트 라이브러리 (구현 단계에서 선정) |
| 배포 | Vercel |

> 프론트엔드 코딩 스타일(들여쓰기 2칸, camelCase/PascalCase, any 타입 금지, 컴포넌트 분리, 반응형 필수)은 사용자 전역 개발 규칙을 따른다.

## 9. 범위 정의 (Scope)

### 9.1 In Scope (MVP)

- Google Sheets → Supabase 자동 수집 파이프라인 (Claude Code 스케줄 기반)
- 대시보드/일별/주별/월별 4개 조회 화면
- 계좌별·구분별(연금/개인투자) 실적 및 비중 시각화

### 9.2 Out of Scope (MVP 제외, 추후 검토)

- 다중 사용자 로그인/권한 관리
- 데이터 웹 화면 내 직접 입력/수정 기능
- 모바일 네이티브 앱
- 알림(수익률 급변 등) 기능
- 다른 증권사 API 직접 연동 (현재는 Google Sheets 경유)

## 10. 리스크 및 고려사항

| 리스크 | 내용 | 대응 방향 |
|---|---|---|
| Google Sheets 구조 변경 | 원본 시트의 컬럼/탭 구조가 바뀌면 수집 스크립트가 깨질 수 있음 | 파싱 로직에 시트 구조 검증 단계 추가, 실패 시 알림/로그 기록 |
| 스케줄 실행 환경 의존성 | Claude Code Windows 스케줄은 로컬 PC 실행 의존적 (PC 꺼짐 시 수집 중단) | 향후 서버리스/클라우드 스케줄러 전환 검토 |
| Supabase 인증정보 관리 | 수집 스크립트와 웹 앱이 각각 DB 접근 필요 | 환경변수로 분리 관리, 웹 앱은 읽기 전용 키 사용 권장 |
| 주/월 집계 기준 모호성 | "마지막 수집일 스냅샷" 기준의 구체적 규칙 미확정 | 개발 착수 전 주차 기준(ISO 등) 확정 필요 |
