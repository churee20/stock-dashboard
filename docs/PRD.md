## 1. 개요

### 1.1 제품 개요

**주식 실적 플래너**는 구글 스프레드시트(Google Sheets)에 정리된 개인 투자 계좌(연금/개인투자) 실적 및 배당 데이터를 자동으로 수집·적재하고, 웹 대시보드에서 조회·분석하며 수집 결과를 자동으로 알림받을 수 있게 해주는 개인용 투자 통계 서비스입니다.

기존에는 구글 스프레드시트를 직접 열어 계좌별 실적을 수기로 확인해야 했으나, 본 서비스는 이를 데이터베이스화하여 대시보드, 일별/주별/월별/배당 추이를 시각적으로 조회하고, 매 수집 완료 시 카카오톡/Slack/구글캘린더로 요약을 자동 수신할 수 있도록 합니다.

### 1.2 핵심 가치

- **자동 수집**: 구글 스프레드시트의 투자 실적·배당 데이터를 스케줄 작업으로 자동 수집하여 DB에 적재
- **이력 관리**: 스프레드시트는 최신 스냅샷만 남지만, DB에는 일자별 이력이 누적되어 추이 분석 가능
- **시각화 조회**: 계좌별/기간별(일·주·월) 실적과 배당 실적을 대시보드와 그래프로 한눈에 확인
- **자동 알림**: 수집이 완료될 때마다 투자 실적 요약을 카카오톡·Slack·구글캘린더로 자동 수신

### 1.3 사용자

- 1인 개인 투자자(서비스 소유자 본인) 전용 MVP. 다중 사용자/로그인 체계는 범위 밖(Out of Scope)으로 별도 확장 검토.

## 2. 배경 및 문제 정의

### 2.1 문제

1. **수기 확인의 번거로움**: 여러 계좌(연금, 개인연금, DC, ISA, 처리투자, 은퇴투자 등)의 실적을 구글 스프레드시트에서 매번 직접 열람해야 함
2. **이력 데이터 부재**: 스프레드시트는 시점 스냅샷 위주라 일별/주별/월별 추이를 비교하기 어려움
3. **시각화 부재**: 표 형태의 데이터만 존재하여 자산 비중, 수익 추이 등을 직관적으로 파악하기 어려움

### 2.2 기존 데이터 원본

| 항목 | 내용 | 참조 |
|---|---|---|
| 주식 실적 수집 | Google Sheets ("1.투자현황(현재)" 탭) | 계좌별 투자원금/현재금액/수익금액/수익률 |

## 3. 목표 및 성공 지표

### 3.1 MVP 목표

- 구글 스프레드시트 데이터를 스케줄 작업으로 Supabase DB에 안정적으로 적재
- 웹에서 계좌별 실적을 대시보드/일별/주별/월별 화면으로 조회 가능하게 배포

### 3.2 성공 지표 (Key Metrics)

| 지표 | 목표 |
|---|---|
| 데이터 수집 성공률 | 스케줄 실행 시 99% 이상 정상 적재 |
| 데이터 최신성 | 최근 수집 시점과 조회 화면 기준일 차이 1일 이내 |
| 대시보드 로딩 시간 | 3초 이내 |
| 조회 화면 커버리지 | 대시보드/일별/주별/월별/배당실적 5개 화면 100% 구현 |
| 알림 전달률 | 수집 완료 시 카카오톡/Slack/구글캘린더 알림 발송 성공(부분 실패 허용, 수집 성공에 영향 없음) |

## 4. 전체 아키텍처 개요

```
[Google Sheets 원본 데이터]
        │  (읽기)
        ▼
[데이터 수집 스크립트]  ← Claude Code(Windows) 스케줄 작업으로 주기 실행
        │  (파싱/변환)
        ▼
[Supabase (PostgreSQL DB)]  ← 일자별 이력 적재
        │  (조회 API / DB 직접 조회)
        ▼
[웹 애플리케이션]  ← Vercel 배포
        │
        ▼
[사용자 브라우저]  ← 대시보드/일별/주별/월별 조회
```

### 4.1 데이터 수집 파이프라인

- **원본**: Google Sheets (`1.투자현황(현재)` 탭, `4.계좌별 비중` 탭, 별도 스프레드시트의 `3.배당금지급` 탭)
- **수집 방식**: Google 서비스 계정(Service Account) 인증으로 Google Sheets API에 접근하여, Vercel Cron이 평일 정해진 시각(KST 16:00)에 `/api/cron/collect` API Route를 자동 호출하는 서버리스 수집 파이프라인 (PC 전원 상태와 무관하게 항상 동작)
- **처리**: 시트 값을 파싱하여 계좌별 실적(투자원금/현재금액/수익금액/수익률), 자산군 비중, 배당 지급 내역(오늘 날짜 이하만, 미래 지급 예정 데이터는 제외)을 당일 스냅샷으로 Supabase에 저장
- **적재 방식**: 동일 계좌·동일 날짜 데이터는 upsert, 날짜가 달라지면 신규 row로 누적 → 일별/주별/월별/배당 추이 데이터의 기반이 됨. 배당은 동일 계좌가 같은 날 여러 종목의 배당을 받을 수 있어 (계좌, 종목코드, 지급일) 기준으로 upsert
- **수집 완료 알림**: 수집 성공 시 계좌별 실적 요약을 카카오톡("나에게 보내기")·Slack(Incoming Webhook)·구글 캘린더(이벤트 등록)로 각각 독립적으로 자동 전송. 알림 중 일부가 실패해도 수집 자체의 성공 응답에는 영향 없음(부분 실패 허용)
- **상세 구현**: `docs/tasks/TASK-006.md`(수집), `docs/tasks/TASK-009.md`(알림), `docs/tasks/TASK-010.md`(배당 수집) 참조

### 4.2 조회 애플리케이션

- **배포**: Vercel
- **DB 연동**: Supabase (PostgreSQL + REST/JS 클라이언트)
- 웹 앱은 데이터를 **입력/수정하지 않고 조회 전용**으로 동작 (데이터 입력은 스케줄 수집 파이프라인이 전담)

### 5.2 화면 1: 계좌별 실적 대시보드 (현재 실적)

**목적**: 전체 투자 현황을 한눈에 파악하는 랜딩 화면

**구성 요소**:

1. **헤더**
   - 서비스명(Investment Dashboard), 부제(투자 실적 현황), 데이터 기준일시(Google Sheets 최종 수집 시각 표시)
   - 탭 내비게이션: 현재 실적 / 일별 추적 / 주별 추적 / 월별 실적

2. **요약 카드 3종**
   - 총 현재금액 (전체 계좌 합계)
   - 총 수익금액 (금액 + 수익률 %)
   - 전일 대비 (증감액 + 증감률 %)

3. **연금 vs 개인투자 비중 (도넛 차트)**
   - 연금 계좌 합계와 개인투자 계좌 합계를 비율로 시각화
   - 범례: 연금 / 개인투자

4. **전체 계좌 자산 비중 (차트)**
   - 전체 계좌별 현재금액 비중 시각화 (도넛/파이 또는 트리맵 등)

5. **계좌별 현재금액 비중 (막대 리스트)**
   - 계좌명(계좌번호 일부 마스킹 표기) + 금액 + 비율 막대
   - 예: 퇴직연금(220-91), 개인연금(기존)(220-34), 개인연금(신)(112-8680), DC계좌(496-3028), 퇴직연금(삼성)(648-8656), 처리투자(미래에셋), 은퇴투자(미래에셋), ISA계좌(648-8656)

6. **계좌별 수익금액 비중 (차트)**
   - 계좌별 수익금액 기준 비중 시각화

7. **상세 현황 테이블**
   - 그룹: 연금 계좌 / 개인투자 계좌 (각 그룹 소계 + 전체 합계 행 포함)
   - 컬럼: 계좌명 | 투자원금 | 현재금액 | 수익금액 | 수익률
   - 계좌 그룹 접기/펼치기(▷/▶) 지원
   - 수익금액/수익률은 양수일 때 강조색(빨강 계열), 표기: `+금액`, `+비율%`

**수락 기준**:
- [x] 요약 카드 3종이 최신 수집 데이터 기준으로 정확히 계산되어 표시된다
- [x] 연금/개인투자 비중 도넛 차트가 실제 데이터 비율과 일치한다
- [x] 계좌별 비중 막대 리스트가 금액 내림차순 등 일관된 정렬로 표시된다
- [x] 상세 테이블에서 연금/개인투자 그룹 소계와 전체 합계가 개별 계좌 합과 일치한다
- [x] 데이터가 없을 경우(수집 전) 빈 상태(empty state) UI가 표시된다

### 5.3 화면 2: 계좌별 실적 (일별)

**목적**: 일 단위로 계좌별 실적 추이를 조회

**구성 요소**:

1. **조회 조건 영역**
   - 계좌 선택 (전체/개별 계좌, 다중 선택 가능)
   - 일자 선택 (기간 조회 - 시작일/종료일)

2. **꺾은선 그래프**
   - 전체 계좌, 연금, 개인투자 구분별 금액 및 수익률 추이를 일별 꺾은선 그래프로 표시
   - Y축: 금액 / 수익률 토글 또는 병행 표시

3. **계좌별 일별 실적 테이블**
   - 컬럼: 날짜 | 구분(전체합계/개인투자/연금 또는 개별 계좌) | 투자원금 | 현재금액 | 수익금액 | 수익률
   - 날짜 내림차순 정렬 (최신일 우선), 날짜별 그룹핑
   - 전체합계 행은 굵게 강조 표시

**수락 기준**:
- [x] 조회 조건(계좌, 기간)을 변경하면 그래프와 테이블이 함께 갱신된다
- [x] 조회 기간 내 데이터가 없는 날짜는 결측으로 명확히 구분되거나 제외된다
- [x] 꺾은선 그래프의 데이터 포인트가 테이블 값과 일치한다
- [x] 기본 조회 기간(예: 최근 30일)이 설정되어 있어 최초 진입 시 바로 데이터가 보인다

### 5.4 화면 3: 계좌별 실적 (주별)

**목적**: 주 단위로 집계된 계좌별 실적 추이를 조회

**구성 요소**:

1. **조회 조건 영역**
   - 일 조회 조건 기반으로 주 단위 집계 대상 기간 지정

2. **계좌 주별 꺾은선 그래프**
   - 금액, 수익률 주별 추이

3. **계좌 주별 실적 테이블**
   - 컬럼: 주차(또는 주 시작일~종료일) | 구분 | 투자원금 | 현재금액 | 수익금액 | 수익률

**집계 규칙**:
- 주 단위 실적은 해당 주의 마지막 수집일(예: 매주 일요일 또는 마지막 영업일) 스냅샷을 그 주 대표값으로 사용
- 주차 표기 기준(ISO 주차 등)은 구현 단계에서 확정

**수락 기준**:
- [x] 주 단위 집계 값이 일별 원본 데이터로부터 일관된 규칙으로 산출된다
- [x] 그래프와 테이블의 주차 표기가 동일한 기준을 따른다
- [x] 조회 조건 변경 시 그래프/테이블이 함께 갱신된다

   - 컬럼: 년월 | 구분 | 투자원금 | 현재금액 | 수익금액 | 수익률

**집계 규칙**:
- 월 단위 실적은 해당 월의 마지막 수집일 스냅샷을 그 달 대표값으로 사용

**수락 기준**:
- [x] 년도/시작월/종료월 조건으로 조회 시 해당 범위의 월별 데이터만 표시된다
- [x] 월 단위 집계 값이 일별 원본 데이터로부터 일관된 규칙으로 산출된다
- [x] 그래프와 테이블의 값이 서로 일치한다

### 5.6 화면 5: 배당실적

**목적**: 계좌별·월별 배당 지급 실적을 조회

**구성 요소**:

1. **조회 조건 영역**
   - 배당종목명 선택 (다중 선택 가능)
   - 조회 기간: 년도 + 시작월/종료월

2. **월별 계좌별 배당 금액 차트**
   - 월별 스택(적층) 막대차트, X축: 월, 막대 내 계좌별 색상 구간으로 배당금액 누적 표시

3. **배당 실적 리스트**
   - 년월 블록마다 연금/개인투자 그룹 접기·펼치기 + 그룹소계 + 그 달 합계 구조(대시보드 상세 테이블과 동일한 패턴)
   - 컬럼: 년월/계좌 구분 | 종목명(종목코드) | 배당수량 | 배당금액(주당) | 배당율 | 배당금액
   - 계좌가 같은 달에 여러 종목의 배당을 받으면 그 계좌 아래에 종목별로 각각 한 행씩 나열(팝업/툴팁 없이 리스트에 항상 노출)

**데이터 처리 규칙**:
- 배당 시트에는 아직 지급되지 않은 미래 예정 배당도 미리 입력되어 있으므로, 수집 시 지급일이 오늘 날짜 이하인 데이터만 반영
- 동일 계좌가 같은 달에 여러 종목의 배당을 받을 수 있으므로 리스트는 종목 단위로 행을 분리해 표시(계좌명은 첫 종목 행에만 표기)

**수락 기준**:
- [x] 배당종목명 다중 선택 및 연도/월 범위 조건 변경 시 차트/리스트가 함께 갱신된다
- [x] 월별 스택 막대차트의 계좌별 구간 합이 그 달 전체 배당금액과 일치한다
- [x] 리스트에서 년월 블록별 연금/개인투자 그룹소계와 개별 계좌 배당금액 합이 일치하고, 그 달 합계가 그룹소계 합과 일치한다
- [x] 리스트에 종목명(종목코드)/배당수량/배당금액(주당)/배당율/배당금액이 개별 행으로 정확히 표시된다
- [x] 배당 데이터가 없는 경우(수집 전) 빈 상태 UI가 표시된다

### 5.7 수집 완료 알림 자동화

**목적**: 매 수집 완료 시 투자 실적 요약을 사용자가 별도로 화면을 열지 않아도 확인할 수 있도록 자동 전송

**대상 채널**: 카카오톡("나에게 보내기"), Slack(Incoming Webhook), 구글 캘린더(이벤트 등록)

**메시지 내용**: 연금/개인투자/전체 각각의 현재금액, 수익금액, 수익률, 전일 대비 증감(카카오톡·Slack은 200자 이내 요약, 구글 캘린더는 상세 설명 + 당일 16:00~16:30 일정으로 등록, 바쁨 표시 없음)

**동작 규칙**:

- 전일 데이터가 없는 경우(최초 실행 등) 전일 대비는 안전하게 처리(에러 없이 "-" 표기)

**수락 기준**:
- [x] 200자 제한 메시지가 실제로 200자를 넘지 않는다(자산 규모가 커져도 자동 축약)
- [x] 한 채널의 전송 실패가 다른 채널 전송이나 수집 성공 응답에 영향을 주지 않는다
- [x] 구글 캘린더 이벤트가 바쁨 표시 없이 등록된다

## 6. 데이터 요구사항

### 6.1 원본 데이터 항목 (Google Sheets 기준)

**투자실적 (`1.투자 현황(현재)` 탭, `4.계좌별 비중` 탭)**
- 계좌명 (예: 퇴직연금, 개인연금(기존), 개인연금(신), DC계좌, 퇴직연금(삼성), 처리투자, 은퇴투자, ISA)
- 계좌번호(또는 식별 코드 일부)
- 계좌 구분: 연금 / 개인투자
- 투자원금
- 현재금액
- 수익금액 (현재금액 − 투자원금)
- 수익률 (수익금액 / 투자원금 × 100)
- 자산군별 현재금액 비중
- 수집 기준일시

**배당 (`3.배당금지급` 탭, 별도 스프레드시트)**
- 지급일, 계좌명, 종목코드, 종목명
- 배당 주식수, 1주당 배당금액, 분배율, 원화 배당금

### 6.2 Supabase DB 설계 (구현 완료 기준)

- **accounts** (계좌 마스터)
  - id, account_name, account_no_masked, account_type(연금/개인투자), created_at
- **account_snapshots** (계좌별 일별 실적 스냅샷 - 이력 테이블)
  - id, account_id(FK), snapshot_date, principal_amount(투자원금), current_amount(현재금액), profit_amount(수익금액), profit_rate(수익률), collected_at
  - UNIQUE(account_id, snapshot_date)로 upsert 대상 지정
- **asset_class_snapshots** (자산군별 비중 스냅샷)
  - id, asset_class(자산군명), snapshot_date, current_amount, collected_at
  - UNIQUE(asset_class, snapshot_date)
- **dividend_snapshots** (계좌·종목별 배당 지급 스냅샷)
  - id, account_id(FK), payment_date(지급일), stock_code, stock_name, dividend_shares(배당주식수), dividend_per_share(1주당배당금액), dividend_rate(분배율), dividend_amount(원화배당금), collected_at
  - UNIQUE(account_id, stock_code, payment_date) — 동일 계좌가 같은 날 여러 종목의 배당을 받을 수 있어 종목코드까지 유니크 키에 포함

- 일별 화면은 `account_snapshots`를 그대로 조회
- 주별/월별 화면은 `account_snapshots`를 주/월 단위로 집계하여 조회
- 배당실적 화면은 `dividend_snapshots`를 월 단위로 집계하여 조회

### 6.3 데이터 수집 규칙

- 스케줄 작업은 평일 1일 1회(KST 16:00) 실행되어 당일 스냅샷을 적재
- 동일 계좌 + 동일 수집일 데이터가 이미 존재하면 최신 값으로 갱신(upsert), 중복 row 생성 금지
- 계좌가 신규로 추가/삭제되는 경우를 대비해 `accounts` 마스터는 수집 시점에 자동 동기화(신규 계좌 발견 시 자동 등록)
- 배당 시트에는 미래 지급 예정 데이터가 미리 입력되어 있으므로, 지급일이 오늘 날짜 이하인 데이터만 수집 대상으로 필터링
- 계좌명은 투자실적 시트와 배당 시트 양쪽에서 DB `accounts.account_name`과 정확히 일치해야 하며, 어느 한쪽만 표기를 변경하면 계좌 매칭 실패 또는 중복 계좌 생성으로 이어질 수 있음(실제 운영 중 사고 사례 있음, `docs/tasks/TASK-010.md` 참고)

## 9. 범위 정의 (Scope)

### 9.1 In Scope

- Google Sheets → Supabase 자동 수집 파이프라인 (Vercel Cron 기반)
- 대시보드/일별/주별/월별/배당실적 5개 조회 화면
- 계좌별·구분별(연금/개인투자) 실적 및 비중 시각화

### 9.2 Out of Scope (추후 검토)

- 다중 사용자 로그인/권한 관리
- 데이터 웹 화면 내 직접 입력/수정 기능
- 모바일 네이티브 앱
- 조건부 알림(수익률 급변 임계치 감지 등 — 현재는 매 수집마다 고정 요약만 발송)
- 다른 증권사 API 직접 연동 (현재는 Google Sheets 경유)
