## 데이터 모델

### 신규 테이블: `stock_holding_snapshots` (종목별 실적&비중)

```sql
create table public.stock_holding_snapshots (
  id uuid primary key default gen_random_uuid(),
  snapshot_date date not null,
  country text not null,               -- 국가(한국/미국)
  stock_code text not null,             -- 종목코드(티커)
  stock_name text not null,             -- 종목명
  quantity numeric not null,            -- 수량
  avg_price_krw numeric,                -- 평단가(원화)
  avg_price_usd numeric,                -- 평단가(달러)
  current_price_krw numeric,            -- 현재가(원화)
  current_price_usd numeric,            -- 현재가(달러)
  valuation_amount numeric not null,    -- 평가액(원화)
  weight_rate numeric not null,         -- 투자비중(%)
  cumulative_dividend numeric not null default 0, -- 누적배당금(원화)
  cumulative_profit numeric not null,   -- 누적수익(원화)
  total_return_rate numeric not null,   -- 총수익률(평가+배당, %)
  collected_at timestamptz not null,
  unique (stock_code, snapshot_date)
);

create index idx_stock_holding_snapshots_date
  on public.stock_holding_snapshots (snapshot_date);
```

- `account_snapshots`와 동일 패턴: `(stock_code, snapshot_date)` 유니크로 upsert, cron 수집 시 자동 누적.
- 현금 행("현금"/currency 없음)은 수집 단계에서 제외.
- 수량 0인 종목(과거 보유했으나 현재 미보유)은 그대로 저장 — pptx slide1의 스택 막대에서 자연히 0 비중으로 표시됨.

### 기존 테이블 `account_snapshots` 백필

- 스키마 변경 없음. 위 매칭표 + "월말일을 snapshot_date로 사용" 규칙으로 `principal_amount`/`current_amount`/`profit_amount`/`profit_rate`를 upsert.
- `collected_at`은 백필 실행 시각으로 기록(실제 수집이 아님을 구분하기 위해 별도 플래그는 두지 않음 — 기존 스키마에 백필 여부 컬럼이 없으므로 과설계 방지).
